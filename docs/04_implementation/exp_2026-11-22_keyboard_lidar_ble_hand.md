# 구현/실험: 키보드(F1~F4) 입력, 블루투스 손, 라이다 막힘 점검

- 작성자: @higogo1
- 날짜: 2026-11-22
- 관련 이슈·PR: #

## 목표
1. 키패드를 키보드 F1~F4 로 바꾸고 문 스테이션이 받게 하기
2. AiHand(micro:bit)를 USB 없이 블루투스로 조종하고, 손가락별 누름 각도 찾기
3. "라이다가 1m 정도 앞만 잡힌다"는 문제 확인

## 구현 내용
| 파일 | 내용 |
|---|---|
| `src/maze_mission/door_station.py` | F1~F4 → 숫자 1~4 (윈도우 `msvcrt` 의 `\x00` + `; < = >`, 리눅스 `ESC O P/Q/R/S`, `ESC [11~`..). 원래는 `\x00` 로 시작하는 키를 모두 버려서 F키가 무시됐음 |
| `src/maze_mission/ble_hand.py` | 블루투스 손 (`MicrobitBleHand`). `hand.MicrobitHand` 와 같은 `send/open/press/close` |
| `src/maze_mission/hand.py`, `mission.py` | `open_hand(cfg)`: `hand.ble` 이 true 면 블루투스, 아니면 USB |
| `src/maze_mission/microbit_ble/` | micro:bit 블루투스 프로그램(`main.ts`), 빌드한 hex, 블루투스로 올리는 `ble_flash.py` |
| `src/maze_mission/lidar_check.py` | 방향(10도)별 빔 응답률 점검 (팀 `lidar.py` 그대로 사용) |
| `src/maze_mission/config.example.json` | 손가락 배치, 실측 누름 각도, `hand.ble` |

부품: 라즈봇 V2 (Pi 5), RPLIDAR A1M8 (펌웨어 1.29, CP2102 USB), micro:bit V2 + Hiwonder 서보 보드 + AiHand, 무선 키보드.

## 실험 조건
- 방 안, 로봇 정지 상태. 라이다는 라이다를 쓰는 다른 프로그램을 끄고 팀 `lidar.py` 로 읽음.
- 손은 파이 블루투스 → micro:bit, 키보드는 바닥, 손을 F1~F4 위에 올려 둠.

## 결과

### 라이다
- 팀 드라이버로 약 **7.4Hz**, 한 바퀴 측정 262개 중 유효 약 **125개(48%)**. 왼쪽 최대 약 4.0m, 뒤 약 3.2m 까지 잡힘
  → 이번에는 **"1m 만 잡힘"이 재현되지 않음**.
- **앞쪽 -60~+30도는 응답률 0~50%** (대부분 "응답 없음"). 같은 자리에서 거리 제한을 풀어도 15cm 안쪽 점은 하나도 없었음.
  A1 은 15cm 보다 가까운 물체를 "응답 없음"으로 주므로, **라이다보다 앞으로 나온 손가락이 빔을 가리고 손가락 사이로 가끔 먼 벽만 보이는 것**으로 판단.
  (어제의 "앞만 1m 정도" 증상도 같은 원인이었을 가능성)
- 참고: A1 은 측정 시작(`A5 20`) 후 첫 데이터까지 약 **1.2초** 걸림. 읽기 시간 제한이 1초면 "응답 없음"으로 오판함 (팀 드라이버는 문제없음).

### 키보드
- F1~F4 입력을 흉내 낸 시험: `F1 F2 ↑ F3 F4 F5 5 q` → `1 2 3 4 5 q` (방향키·F5 는 무시). 정답 `421` → 열기, `412` → 다시 입력.

### 블루투스 손
- 파이에서 `BBC micro:bit [tepag]` 발견, **페어링 없이 연결**, Nordic UART 서비스 있음.
- 원래 올라가 있던 블루투스 프로그램은 팀 USB 형식(`50,130,130,130,130,90,300`)과 다른 형식이라 모든 명령에 `ERR <받은 줄>` → 새로 만듦.
- 팀 USB hex 안의 MakeCode 원본을 꺼내 서보 구동 방식을 확인하고(아래), 같은 구동에 블루투스 UART 입력만 바꾼 `main.ts` 작성.
  - micro:bit → Hiwonder 서보 보드: P12/P8 115200, `55 55 len 03 6 tL tH [id pL pH]x6`, 펄스 500 + 각도×2000/180
- 블루투스 UART 는 **한 번에 20바이트** → 한 줄이 길면 쓰기가 거부됨(`Unlikely Error`). 명령을 `s<i>,<각도>` / `m<ms>` 로 쪼갬.
- **USB 없이 블루투스로 올림**: micro:bit 펌웨어 hash 와 빌드한 hex 의 hash 가 같아(`4a2f0065895ea2ba`) MakeCode 부분 업데이트 가능. 10KB, 7초, 재전송 0회.
- 실측 누름 각도 (펴짐 130 → 작을수록 굽힘):

| 키 | 손가락 | 누름 각도 |
|---|---|---|
| F4 | 검지 | 89° |
| F3 | 중지 | 68° |
| F2 | 약지 | 78° |
| F1 | 새끼 | 74° |

- 새끼(F1)는 손 각도 때문에 덜 눌리는 편. **차를 조금 왼쪽에 맞추면 눌림**.
- 앞바퀴 앞에서 키를 누르는 손까지 **21cm**.

## 문제와 해결
| 문제 | 해결 |
|---|---|
| F1~F4 가 문 스테이션에서 무시됨 | `read_keys()` 가 F키를 숫자로 바꾸도록 수정 |
| 손 블루투스 프로그램 형식을 모름 | 팀 USB 프로그램 원본에서 구동 방식 확인 → 새 블루투스 프로그램 |
| 블루투스 20바이트 제한 | 짧은 명령으로 나눠 보냄 |
| micro:bit 을 PC 에 꽂지 않고 올리기 | MakeCode 부분 업데이트(Partial Flashing) 프로토콜로 파이에서 직접 올림 (`ble_flash.py`) |
| 라이다 앞쪽이 손에 가려짐 | (미해결) 라이다를 손보다 높이 올리기 |
