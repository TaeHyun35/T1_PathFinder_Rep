# 06_progress — 전체 계획 + 진행 기록

> ## ⚠ 추가 전용 폴더
> **이 폴더의 기존 파일은 누구도 수정·삭제·이름 변경할 수 없습니다.**
> **본인이 진행한 내용을 새 파일로 추가만 합니다.**
> PR마다 `progress-guard` 검사가 자동으로 확인하고, 위반한 PR은 merge할 수 없습니다.
> (예외: 이 README는 규칙 변경 시에만 관리자 리뷰를 거쳐 수정합니다.)

## 구조

```
06_progress/
├── README.md            # 이 문서 (규칙 + 템플릿)
├── plan/                # 전체 계획 — plan_v0.md, plan_v1.md, ...
└── log/                 # 개인 진행 기록 — YYYY-MM-DD_GitHubID.md
    └── assets/          # 기록에 넣는 이미지 — YYYY-MM-DD_GitHubID_설명.png
```

## 규칙

| 항목 | 규칙 |
|---|---|
| 진행 기록 | `log/YYYY-MM-DD_본인GitHubID.md` **새 파일**로 추가. 같은 날 두 번째부터 `_2`, `_3` |
| 본인 기록만 | 파일 이름의 ID가 **PR 작성자 GitHub ID와 같아야** 합니다 (대소문자 무관) |
| 이미지 | `log/assets/YYYY-MM-DD_본인GitHubID_설명.확장자` |
| 전체 계획 | 기존 계획을 고치지 않고 `plan/plan_vN.md`를 새로 추가. **가장 큰 번호가 최신 계획**이며, 맨 위에 "이전 버전 대비 변경점"을 적습니다 |
| 정정 | 이전 기록이 틀렸으면 고치지 말고 다음 기록의 "정정" 항목에 적습니다 |
| 금지 | 기존 파일 수정·삭제·이름 변경, 다른 사람 ID로 된 파일 추가, 형식에 맞지 않는 파일 이름 |

## 진행 기록 템플릿

아래를 복사해 `log/YYYY-MM-DD_본인GitHubID.md`로 저장합니다.

```markdown
# 진행 기록 YYYY-MM-DD — @GitHubID

## 한 일
-

## 결과
(수치, 사진, 영상·PR 링크)

## 문제점

## 다음 할 일
-

## 관련 이슈·PR
-

## 정정 (필요할 때만)
- YYYY-MM-DD 기록의 ○○ → △△
```

## 계획 템플릿

```markdown
# 전체 계획 vN

- 작성: @GitHubID / 날짜: YYYY-MM-DD
- 이전 버전 대비 변경점:

## 목표
## 범위 (하는 것 / 안 하는 것)
## 마일스톤
## 주차별 일정
## 역할 분담
## 위험 요소
```
